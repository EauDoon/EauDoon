## What landed

A new `scripts/drift.mjs` plus a test suite and a CI workflow. The drift detector compares the per-project `wavesTouched` arrays against the top-level `portfolioWavesCompleted`, walks the catalog for duplicate ids, and checks that `assessedOn` has not aged past the configured tolerance (default 45 days). It runs offline and reads only the catalog on disk.

## Detection rules

- A wave that appears in two or more `projects[].wavesTouched` arrays but is missing from `portfolioWavesCompleted` is flagged. Global-only phases (no per-project touch) are permitted.
- A `lastAudited` date newer than `catalog.assessedOn` is flagged.
- An `assessedOn` older than `--max-age-days` (default 45) is flagged.
- Duplicate project ids are flagged.

## Schedule

`.github/workflows/drift.yml` runs on every push that changes the catalog or related scripts, on every PR that touches those paths, weekly on Mondays at 06:00 UTC, and on `workflow_dispatch`.

## CLI

- `node scripts/drift.mjs --check` — exits non-zero when any issue is detected.
- `node scripts/drift.mjs --json` — emits a structured report; exit code mirrors --check.
- `node scripts/drift.mjs --check --max-age-days 60 --today 2026-09-23` — override tolerance and reference date for replays.

## Coverage

8 new tests in `test/drift.test.mjs` cover passing catalogs, global-only phases, missing top-level waves, lastAudited drift, age drift, and duplicate ids. The full suite (`node --test`) is now 49 cases; 48 pass and 1 POSIX-FIFO test is platform-skipped on Windows.

The drift check is appended to `npm run check` so PRs touching catalog files fail locally and in CI when the catalog drifts.
